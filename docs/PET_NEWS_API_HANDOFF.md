# 📰 Bow-Meow-Wow — Pet News API 요청서

Pet News 탭에 실제 반려동물 관련 뉴스를 하루 10개 정도 보여주는 기능이 필요합니다. 프론트는 아래 스펙을 가정하고 화면(`src/pages/PetNewsPage.jsx`)을 이미 만들어뒀는데, 지금은 API가 없어서 에러 화면만 뜹니다.

---

## ⚠️ 가장 중요한 부분: "진짜 뉴스"여야 합니다

Gemini(LLM)에게 그냥 "반려동물 뉴스 10개 써줘"라고 시키면 **실제로 존재하지 않는 기사를 그럴듯하게 지어낼 수 있습니다** (hallucination). 이건 뉴스 UI로 보여주기엔 위험합니다 — 없는 기사인데 실제 언론사 이름이나 없는 URL을 붙여서 사용자에게 "진짜 뉴스"인 것처럼 보이면 신뢰 문제가 생깁니다.

그래서 다음 중 하나로 부탁드립니다:

1. **Gemini + Google Search grounding** (Gemini API의 grounding/tool-use 기능으로 실제 검색 결과에 근거해서 응답하게 하는 방식) — 실제 검색된 기사 URL/출처를 응답에 포함시킬 수 있으면 이게 제일 좋습니다.
2. 또는 **실제 뉴스 API/RSS**(네이버 뉴스 API, Google News RSS 등)로 기사 목록을 가져오고, Gemini는 요약문(summary)만 생성하는 데 쓰기 (기사 자체는 진짜, 요약만 AI가 다듬는 방식 — 가장 안전).
3. 위 둘 다 여의치 않으면, 최소한 **실제 존재하는 URL을 확인할 수 있는 방식**으로 구현해주시고, 순수 생성(grounding 없는 텍스트 생성)만으로 기사를 "만들어내는" 방식은 피해주세요.

편하신 방식으로 결정하시면 되고, 어떤 방식으로 하셨는지만 알려주시면 프론트에서 참고하겠습니다.

---

## API 명세 (제안)

### `GET /api/news` (로그인 불필요, 공개 API — `/api/clinics`와 동일한 패턴)

**Response 200 OK**
```json
[
  {
    "id": 1,
    "title": "여름철 반려견 열사병 주의보, 수의사들이 전하는 예방법",
    "summary": "기온이 오르며 반려견 열사병 환자가 늘고 있다. 전문가들은...",
    "source": "OO일보",
    "url": "https://example.com/news/12345",
    "publishedAt": "2026-09-13T09:00:00+09:00"
  }
]
```

- `summary`: 선택이지만 있으면 좋습니다 (한두 문장 요약)
- `source`: 언론사/출처명
- `url`: 실제 원문 링크 (프론트에서 새 탭으로 열림)
- `publishedAt`: ISO 8601, 없으면 프론트에서 시간 표시를 생략합니다
- 하루 약 10개, **매일 자정(00:00, 한국 시간 KST 기준으로 부탁드립니다)에 갱신**

### 갱신 방식

- 매일 자정에 배치/크론으로 새로 가져와서 DB나 캐시에 저장해두고, `GET /api/news`는 그 저장된 결과를 그대로 내려주는 방식을 가정합니다 (매 요청마다 Gemini를 호출하는 건 비용/속도상 비효율적일 것 같습니다).
- 갱신 실패 시(예: API 에러) 마지막으로 성공한 캐시를 그대로 유지해주시면 좋겠습니다 — 빈 배열보다는 어제 뉴스라도 보이는 게 낫습니다.

## 구현 완료 (답변)

1. **방식**: Google News RSS(API 키 불필요)에서 실제 기사를 그대로 가져와 title/source/url/publishedAt을 채웁니다. Gemini 요약조차 쓰지 않기로 결정 — summary까지 AI가 만들면 "제목만 보고 없는 내용을 지어낼" 여지가 있어서, 1차 버전은 AI를 아예 안 태우는 쪽으로 갔습니다. `summary`는 현재 항상 `null`이며, 프론트는 이미 이 경우를 정상 처리합니다(요약 없으면 그냥 안 보여줌).
2. **KST 자정 갱신**: 맞습니다, 매일 00:00 Asia/Seoul에 APScheduler로 앱 내부 크론이 자동 갱신합니다 (별도 인프라 설정 불필요).
3. **개수**: 정확히 10개 고정이 아니라 최대 10개 (그날 검색되는 기사 수에 따라 더 적을 수 있음, 실제로는 거의 항상 10개).

갱신 실패해도 이전 캐시가 유지되는 구조로 확인했습니다. 실제 배포 서버로 10개 응답과 프론트 렌더링까지 검증 완료했습니다 — 이 요청서는 클로즈합니다.

## 참고: 이번 요청과 별개로 — 백엔드 작업 필요 없는 변경사항

같이 진행한 다른 화면 변경들은 **백엔드 API 변경이 필요 없어서 별도 요청 없습니다** (참고용으로만 남겨둡니다):
- "Clinic Finder" → "Map"으로 이름만 변경, 검색 UI를 지역+카테고리 드롭다운에서 자유 텍스트 검색(매장명/지역/카테고리 통합)으로 변경 — 기존 `GET /api/clinics` 응답 그대로 프론트에서 클라이언트 필터링으로 처리했습니다.
- AI 챗봇에서 "상담 대상 반려동물" 드롭다운을 없애고, 대화 시작 시 AI가 먼저 "어떤 반려동물인가요?" 묻고 사용자가 채팅으로 답한 이름을 프론트에서 등록된 펫 이름과 매칭해서 `petId`를 자동으로 채웁니다 — 기존 `POST /api/chat` 그대로 사용합니다.
